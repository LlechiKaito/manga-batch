# ユーザーストーリー作成計画

## 概要
S3バケットに保存されたepubファイル（漫画）を「話」単位に分割するバッチシステムのユーザーストーリーを作成する。

---

## ステップ

- [x] **Step 1: 前提条件・用語の整理**
  - システムに関わる用語（epub、話、目次ページ等）の定義を明確にする
  - 対象となるepubファイルの形式・構造を整理する

  [Question] epubファイルの形式について確認します。
  1. 対象のepubは漫画（画像ベース）ですか？それともテキストベースですか？
  2. 「目次」はepub内のどこに存在しますか？（例: epub標準のナビゲーション（toc.ncx / nav.xhtml）、または本文中の画像ページとして存在する等）
  3. 「話」とは具体的に何を指しますか？（例: 第1話、第2話のようなエピソード単位）
  4. 1つのepubファイルには複数の「話」がまとめられている（例: 単行本形式）という理解で正しいですか？

  [Answer]
  1. 漫画
  2. epubの中に画像として存在するので、それを読み込みます
  3. 第1話、第2話のようなエピソード単位。目次で分割されている単位ですね
  4. はい

- [x] **Step 2: アクター（利用者）の定義**
  - バッチを起動するアクターを特定する（例: 管理者、スケジューラ、外部トリガー等）

  [Question]
  1. このバッチは誰が・何がトリガーしますか？（例: 手動実行、スケジュール実行、S3イベントトリガー等）
  2. バッチの実行状況を確認するユーザーはいますか？（管理画面等）

  [Answer]
  1. 手動実行
  2. 一旦なし（コンソールから確認します）

- [x] **Step 3: ユーザーストーリーの洗い出し**
  - Step 1, 2の回答をもとに、以下の機能領域ごとにユーザーストーリーを列挙する
    1. S3からのepubファイル取得
    2. 目次ページの読み取りと「話」の特定
    3. 各「話」の最初と最後のページの特定
    4. epubファイルの分割
    5. 分割後のepubファイルのS3への格納
    6. エラーハンドリング・ログ

  [Question]
  1. 処理対象のepubファイルはどのように選定しますか？（例: 特定のS3パスの全ファイル、ファイル名パターン、外部から指定等）
  2. 分割後のepubファイルの命名規則やS3上の格納パスに要件はありますか？
  3. 処理済みのepubファイルの扱いはどうしますか？（削除、移動、フラグ管理等）
  4. エラー発生時の要件はありますか？（リトライ、通知、ログ等）

  [Answer]
  この辺りは検証なので考慮しなくていいです。
  S3バケットにテスト用の作品を1つだけ置く想定です

- [x] **Step 4: 各ユーザーストーリーの詳細記述**
  - 各ストーリーについて以下を記述する
    - ストーリー文（As a ～, I want ～, so that ～）
    - 受入条件（Acceptance Criteria）
    - 優先度

- [x] **Step 5: ユーザーストーリーのレビュー・最終化**
  - 全ストーリーの整合性を確認
  - 抜け漏れがないか確認
  - ユーザーの最終承認を得る
